DETERMINISTIC GATE — use process exit status for facts, then send diagnostics to AI:
```yaml
api_version: 1
steps:
  - {id: build, cmd: ["cargo", "test"], effects: workspace, on_error: "goto:fix"} # direct spawn
  - id: ship
    cmd: ["sfh", "--version"]  # effects is what the process touches, not its purpose
    effects: read
    route: [{goto: end}]       # always terminate a branch
  - id: fix
    tool: codex
    access: full               # AI steps must declare access: read | write | full
    prompt: "{{steps.build.stderr_file}}: read this file and fix the failure"
    route: [{goto: build}]
```
This form behaves the same on every OS. Pin verified AI CLIs with `require_version: ">=1.2, <2.0"`; mismatch fails before any flow step.
Use `sh -c` only to join multiple commands; on Windows it requires Git Bash.
For long command input, pass the rendered prompt as `{{prompt_file}}` instead of shell quoting it.
AI GOAL VERDICT — require exactly one final-line token and fail closed:
```yaml
api_version: 1
steps:
  - id: judge
    tool: codex
    access: read
    prompt: "Assess the goal. Last line: ACHIEVED, UNMET, or UNCLEAR."
    route:
      - {when_last_line_is: ACHIEVED, goto: achieved}
      - {when_last_line_is: UNMET, goto: unmet}
      - {when_last_line_is: UNCLEAR, goto: unclear}
      - {goto: unclear}
  - {id: achieved, cmd: ["sfh", "--version"], effects: read, route: [{goto: end}]}
  - {id: unmet, cmd: ["sfh", "--version"], effects: read, route: [{goto: fail}]}
  - {id: unclear, cmd: ["sfh", "--version"], effects: read, route: [{goto: fail}]}
```
BOUNDED REWORK WITH DEGRADATION:
```yaml
api_version: 1
steps:
  - id: revise
    tool: codex
    access: full
    max_visits: 3
    on_max_visits: goto:degraded
    prompt: "Revise using: {{steps.review.output | optional}}"
  - id: review
    tool: codex
    access: read
    prompt: "Review. Last line: PASS or REVISE."
    route:
      - {when_last_line_is: PASS, goto: end}
      - {goto: revise}
  - {id: degraded, cmd: ["sfh", "--version"], effects: read}
```
Limits are checked on entry, so the node entered first in a loop reaches its limit first.
PARALLEL MEMBERS / ONE BRANCH PER ITEM — when_members counts verdicts, never text:
```yaml
api_version: 1
vars: {targets: "--version\n--help"}
steps:
  - id: review
    parallel:                  # members need on_error: continue, or one failure skips the route
      - {id: rev_a, tool: codex, access: read, on_error: continue, prompt: "Last line: PASS or FAIL."}
      - {id: rev_b, tool: codex, access: read, on_error: continue, prompt: "Last line: PASS or FAIL."}
    route:                     # a member votes only if it exited 0 AND its own last line matches
      - {when_members: {last_line_is: PASS, all: true}, goto: per_target}
      - {goto: fail}
  - id: per_target
    foreach: {from: "{{vars.targets}}", split: lines}
    cmd: ["sfh", "{{item}}"]
    effects: read
```
HUMAN ANSWER — the command waits; timeout_sec is the deadline:
```yaml
api_version: 1
steps:
  - {id: approval, cmd: ["approval-cli", "wait", "--question", "Ship this build?"], effects: read, timeout_sec: 3600}
```
DETACH AND COLLECT: `sfh run flow.yaml --detach` → `sfh status` → `sfh wait` / `sfh stop`
DRIVING SFH FROM A PROGRAM — add --json; stdout is then the envelope and nothing else:
```text
sfh preflight flow.yaml --json   # free: binaries (incl. every cmd: program), flags, protocols, gaps.
sfh plan      flow.yaml --json   # what would run, with prompts redacted. Starts nothing.
sfh run       flow.yaml --json --detach   # returns {run_dir, next_actions:[{argv:[...]}]}
sfh wait <run-dir> --json        # blocks, then {ok, state, result, result_file}
sfh status <run-dir> --json      # add --json to stop/workspaces too
```
Pass the run dir explicitly; omission selects the NEWEST. Branch on stable `error.code`, not messages.
PROTOCOL SALVAGE: set `on_error: continue`, then `{when_protocol_is: invalid, goto: salvage}`; failed output remains in `steps.X.outputs`.
WORKSPACE AND CONTEXT — opt-in; omit both and every step runs in the caller's cwd as before:
```yaml
api_version: 1
workspace: {mode: git-worktree} # one explicit worktree for the whole writer run
contexts:                       # file paths are literal; dynamic content uses template:
  rules: {inline: "be brief"}  # named, ordered, hashed; recorded in <tag>.context.json
steps:
  - id: edit
    effects: workspace         # read | workspace | external | unknown (cmd: defaults to unknown)
    context: [rules]
    replay: {unfinished: stuck}   # a crashed external effect: stuck/fail launch nothing
    exit_conflict: trust_protocol # ONLY for a CLI that exits non-zero after a certified-good turn
    outcomes: {2: {result: continue, label: more_to_do}}  # exit code -> meaning; route with when_label_is
    cmd: ["sh", "-c", "true"]
```
`--state-dir` keeps workspaces out of the repository; `--profiles f.yaml` swaps tools without editing the flow.
A resume is refused if the flow, an overlay, a context file or a tool version moved (--force-resume), or if the
workspace changed with no unfinished step to explain it (--adopt-workspace). They are different questions.
If you had to FIX the flow, resume is not the tool: `--carry-budget-from <run-dir>` starts a new run holding the
old one's spend (steps, per-step visits, cost, time), so a corrected retry does not silently reset its budget.
Details: README. If unsure: `sfh validate flow.yaml` and `sfh run flow.yaml --dry-run`.
